## 요청
트렌드가 “오늘 하루” 기준이면 어울리지 않으니 최근 한 달처럼 기간을 넓히자는 제안 → 논의 후 “최근 7일 중심 + 시즌은 한 달 앞 미리보기”로 결정, 추천대로 진행.

## 15차에서 바뀐 것
- **구글 인기 검색어 7일 누적** (`src/history.js`, `src/index.js` `realTrends`/`histRead`/`histWrite`): 날짜(KST)별 목록(label·q·뉴스 제목 2개·검색량)을 저장. 오늘 목록은 같은 날 저장분과 합침(같은 날 여러 번 받아도 하루로 셈). 지난 6일치를 읽어 `mergeHistory`로 합침: 오늘 있거나(또는 최근 2일 안에 보였고 이틀 이상 등장), 점수 = 등장한 날 수 + (오늘 있으면 1.5), 같으면 오늘 순위. 그 뒤 기존 필터(NEWSY·인물·선정·종교·AI 선별)를 누적 목록 전체에 적용. 오늘 구글을 못 받아도 지난 며칠 기록으로 칩을 채움. 캐시 키 `gt1`→`gt2`.
  - 저장소: `env.TREND_KV`(선택, 9일 보관)가 있으면 KV, 없으면 Cloudflare 캐시(`https://cache.local/gth?d=날짜`, 9일). 캐시는 데이터센터별 best-effort라 **앱을 연 날만 쌓입니다**. 저장·읽기 실패는 모두 무시하고 오늘 목록으로 동작.
  - `scheduled` 핸들러 추가(크론이 켜져 있으면 하루 한 번 쌓음). `wrangler.toml`에 KV·크론 설정을 **주석으로만** 안내(켜지 않음).
- **베스트 사진 최신순 섞기** (`popularPhotos`): Pixabay와 Unsplash는 문서상 기간 지정이 없고 정렬(popular/latest)만 있음(Pixabay는 문서로 확인, Unsplash는 기존 코드의 `order_by` 사용 + 래퍼 문서에 기간 지정 없음). Pixabay는 에디터 추천의 최신순·인기순을 같은 쪽 번호로 받아 번갈아(요청 2번, 장수는 절반씩), Unsplash는 무료 한도(시간당 50회)를 생각해 요청 1번: 홀수 쪽 최신순 / 짝수 쪽 인기순(쪽 번호는 `ceil(page/2)`).
- **에디터 픽(커먼즈 우수 사진)**: 시작 시기를 `day % 90`주 전에서 `day % 5`주 전(0~4주 전)으로 → 최근에 뽑힌 사진부터, 쪽이 넘어가면 더 오래된 것.
- **시즌 주제** (`src/season.js`): 행사는 최소 30일 전부터(`PREVIEW_DAYS`), 달의 마지막 10일(`NEXT_MONTH_DAYS`)에는 다음 달 계절 주제를 하나 미리 추가(12월→1월 포함).
- README·wrangler.toml 주석 갱신. 서비스워커·화면 코드 변경 없음(캐시 버전 그대로).

## 배포 후 확인할 것
1. 처음 며칠은 기록이 쌓이는 중이라 이전과 비슷하게 보이는 것이 정상(첫날은 오늘 목록만). 3~4일 뒤 트렌드 칩에 며칠째 계속 나오는 말이 앞에 오는지.
2. 앱을 안 연 날이 많으면 기록이 비는 것은 한계. 필요하면 KV + 크론 켜기(wrangler.toml 주석 참고): KV 네임스페이스 만들기 → 워커에 `TREND_KV` 바인딩 → 크론 주석 해제.
3. 트렌드 ‘베스트’에 요즘 올라온 사진이 섞여 나오는지(Pixabay/Unsplash 호출이 늘었으므로 Unsplash 한도 오류가 없는지).
4. 시즌 칩: 오늘(10/28) 기준 빼빼로데이·수능·늦가을이 보이는지, 11월 말에는 대림절·크리스마스.
