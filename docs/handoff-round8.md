# 이미지피드 — 8차 작업 결과와 9차 인계 (2026-10-27)

저장소: https://github.com/Joonwang-Ji/imagefeed (main). 변경 파일을 ZIP(imagefeed-round8.zip)으로 전달 → GitHub 웹에서 같은 경로로 덮어쓰기 업로드(새 파일 `public/safety.js`, `tests/safety.test.mjs`, `docs/handoff-round8.md`).
키: Pixabay, Unsplash, 카카오, 네이버 등록됨. 원칙(바꾸지 말 것): 검색·조회 기록 저장 금지, 공포·잔혹 해제 불가, 선정성은 기본 블러+설정에서 해제 가능, 사용자는 본인과 소수 지인(성인).

## 신고 내용 (7차 사용 후기)
1. 트렌드(주로 위키백과)에 성행위 그림·석상·성기 관련 항목이 가끔 나옴. 블러가 아니라 **아예 차단**해도 좋음. 단 미술작품 등 역사적인 검색은 예외, 트렌드를 훑다가 당황스럽지 않게만.
2. 북마크해 둔 성경책(손이 올려진 사진, 펼친 책)이 블러됨. 엉뚱한 블러를 전반적으로 손봐 달라.
3. '패턴 가을' 검색: 네이버만 40개 나오고 끝, [더 보기] 없음. 소스 칩 숫자는 각각 꽤 많이 받았는데 화면엔 네이버뿐. (한참 기다린 뒤 다시 보니 불러와져 있었음)

## 결정한 해석 (확인 필요하면 알려 주기)
- **트렌드만** 엄격하게: 성행위·성기 표현은 미술·역사 자료여도 뺌, 나체 표현은 미술·역사 맥락이 있으면 남기고 블러. 일반 **검색**은 이전처럼 블러(미술·역사 검색을 막지 않음). "미술·역사 예외"는 검색에서 막지 않는다는 뜻으로 해석함.

## 8차에서 바뀐 것
- **서버 필터** (`src/filters.js`): `isExplicit`(성행위·성기), `isNude`(나체), `hasArtContext`(조각·그림·유적 등) 추가. 형성기·자위대·성교육·정액제·오럴B·Sussex 같은 평범한 말은 걸리지 않게 예외 처리. 검색 결과의 선정성 키워드(블러)에도 노골적 표현이 포함됨.
- **트렌드** (`src/index.js`): 위키 문서의 짧은 설명(pageterms)과 사진 파일 이름을 제목과 함께 판단(`ctx`, 화면에는 보내지 않음). 판정: 노골적 표현 → 제외 / 나체+미술 맥락 → 블러로 유지 / 나체만 → 제외 / 그 외 선정 키워드 → 블러.
- **브라우저 AI 판정** (`public/safety.js`, 새 파일): 점수만 보지 않고 (1) 기준 상향(Sexy 0.7→0.85 등) (2) 살색 비율(`ColorTools.skin`) 확인 (3) 제목·태그가 성경·책·교회·음식 등이면 아주 확실할 때만. 노골적(explicit, Porn·Hentai 높음)인 이미지는 **트렌드에서 카드를 제거**(블러 설정을 꺼 둬도 검사). 북마크도 이미지(blob)로 다시 검사.
- **블러 해제**: 뷰어의 [블러 해제] 버튼 → 그 이미지는 블러하지 않음(북마크한 이미지는 북마크에 기억, 그 외는 화면을 연 동안만).
- **북마크 마이그레이션**: 새로 저장하는 북마크에 `adultSrc`("kw"=키워드, "ai"=AI), `safe` 저장. 열 때 `adultSrc === "kw"` 인 것만 저장값을 따르고, AI가 걸었던 것(예전 기록 포함)은 지금 기준으로 다시 검사. 예전에 오탐으로 저장된 성경책 북마크가 이걸로 풀림.
- **피드 (패턴 가을)**: 재현 결과, 소스 가중치·한글 보정·등급 배수로 네이버가 60장 자리를 거의 차지하고, 첫 화면은 가장 느린 소스가 올 때까지(최대 16초) 12장만 올렸으며, 불러오기가 한 번 멈추면 [더 보기]도 [관련도 낮은 결과 보기]도 안 나오는 막다른 상태가 가능했음.
  - 한 소스의 상한(`Feed.pick`): 보여 줄 만한 이미지를 가진 소스가 4개 이상이면 35%, 3개 45%, 2개 이하 55%(최소 12장). 다른 소스가 모자라면 상한 없이 채움. 이미 올라간 카드는 안 움직임.
  - 첫 화면 대기 4초 상한(타이머): 느린 소스가 있어도 4초에 받은 것으로 화면을 채움. 늦게 온 결과는 대기열에 합류해 [더 보기]로 보임.
  - 번역 요청 7초 시간 제한(영어 소스가 번역을 무한정 기다리지 않게), 12초 넘게 이미지가 안 열리는 소스는 더 이상 기다리지 않고(`holding` 만료) 12.5초 뒤 자동 재개.
  - 막다른 상태 해소: 모든 소스가 이미지를 기다리는 중(`stuck`)이면 [더 보기]와 안내("일부 소스의 이미지가 아직 열리는 중이에요")를 보이고, 직접 누르면 기다리지 않고 이어 불러옴(`holdOff`). 보여 줄 것이 없고 접힌 결과만 있으면 [관련도 낮은 결과 N개 보기]도 바로 표시. 불러오기 중 오류가 나도 `loading` 이 true 로 남지 않게 try/catch.
- 서비스워커 v9(`/safety.js` 캐시), README 갱신.

## 검증
- 서버(트렌드 판정 8개 추가), 피드(소스 독차지·느린 소스·막다른 상태 10개 추가), 안전(순수 함수 14개 + 화면 12개, 새 파일), 기존 색상·관련도·화면 테스트 모두 통과.
- 일부러 되돌리면 실패함을 확인: 소스 상한 제거, 4초 타이머 제거, 막다른 상태 버튼 제거, 직접 누를 때 기다림 해제 제거, 트렌드 노골적 이미지 제거 해제, 예전 점수 기준 복귀, 북마크 재검사 제거, 서버 노골적 표현 제외 해제, 미술 맥락 예외 제거.
- 이 환경은 외부 인터넷·Workers AI·실제 브라우저(nsfwjs, canvas)가 없음 → 실제 응답·모델 점수는 미확인. 특히 **'패턴 가을'의 정확한 원인은 재현하지 못함**(증상은 위 세 가지 원인의 조합으로 설명되지만 실제 기기에서 확인 필요), 살색 비율 기준(0.12~0.4)과 AI 점수 기준은 가정값.

## 배포 후 실제 기기에서 확인할 것
1. 트렌드: 새로고침(또는 30분 뒤)해서 위키 항목을 여러 번 훑어 보고 성행위·성기·노골적 그림/석상이 아직 보이는지. 보이면 어떤 문서·이미지인지(제목) 알려 주기 → 단어/기준 추가.
2. 성경책 북마크가 블러 없이 열리는지, 펼친 책·손 사진이 검색에서 블러되는 빈도. 여전히 엉뚱하면 해당 이미지 제목과 함께 알려 주기(뷰어 [블러 해제]로 임시 해제 가능).
3. 진짜 선정적인 이미지는 여전히 블러되는지(기준을 올려서 놓칠 가능성).
4. '패턴 가을' 재검색: 네이버·Pixabay·Unsplash·위키 등 여러 소스가 첫 화면에 섞이는지, [더 보기]가 나오는지, 막혀 보이면 아래 안내 문구/[더 보기] 확인. 증상이 남아 있으면 소스 칩 숫자와 화면 장수, 시간(몇 초 후 변했는지)을 알려 주기.

## 알려진 한계·조정 포인트
- 소스 상한 비율(0.35/0.45/0.55), 4초, 12초, 살색 비율 기준은 각각 `Feed.pick`, `next()`, `holding`, `public/safety.js` 상단에서 조정.
- 트렌드의 미술·역사 맥락 판정은 위키 짧은 설명·제목·파일 이름의 단어 기준이라, 설명이 없으면 나체 표현도 맥락 없음으로 보아 제외됨.
- 살색 비율 계산은 canvas 필요(브라우저). 못 읽으면 중간값 0.3으로 보고 점수만으로 판단.
- 오래된 북마크의 키워드 블러 기록은 `adultSrc` 가 없어 AI 재검사로 대체됨(키워드로만 걸렸던 드문 경우 블러가 풀릴 수 있음).
