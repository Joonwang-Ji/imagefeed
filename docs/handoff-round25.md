## 요청 (두 가지)
1. 서버를 비우거나 "새로 시작"을 해도, **북마크가 남아 있으면 그 이미지·주제가 계속 취향(가산점)으로 쓰였으면** 함. 앱의 지향점("내가 좋아하는 것을 자주 추천")과 같은 노선이라고 확인함. 점수는 시간이 지나 줄어들되 **바닥값은 남기는** 방식을 추천안으로 채택.
2. 스크롤을 내리면 다시 위로 올라가기 힘듦 → 위/아래 버튼 + 하단 탭을 다시 누르면 맨 위로.

## 25차에서 바뀐 것
### A. 북마크 → 취향 (public/app.js, interests.js, taste.js)
- **문제(24차까지)**: 북마크를 활동 기록(`act`)으로 옮기는 `migrate()` 가 `actMig1` 플래그로 **기기당 딱 한 번**만 실행됐고, 취향 점수(`taste`)는 북마크할 때 +3 을 한 번만 받아 시간이 지나면 사라짐. 그래서 "새로 시작"·모두 지우기·감쇠 뒤에는 북마크가 있어도 관심사 묶음·맞춤 피드가 비었음.
- **`ACT.backfill()`** (migrate 대체): 북마크 중 활동 기록에 없는 이미지를 북마크 1개 = 3점(담은 시각 그대로)으로 채움. 선정적으로 판정된 것(`adult && !safe`)과 취향 학습 꺼짐·비공개 모드에서는 하지 않음.
- **`Taste.floorFrom(list)`** (새): 북마크의 단어·색·톤에 바닥 점수를 줌. 단어는 북마크 1개당 1점(같은 단어가 여러 북마크에 있으면 올라가되 **상한 4**), 색은 ×0.5(상한 2), 톤은 ×0.6(상한 2.4). 이미 더 높은 점수는 건드리지 않고(내려가지 않음), **뺀 단어(mute)는 받치지 않음**. 바뀐 게 없으면 저장하지 않음(여러 번 불러도 같은 결과).
- **바닥값 `Interests.BM_FLOOR = 1.6`** (> `MIN_W` 1.5): 북마크로 남은 이미지의 활동 중요도는 감쇠(하루 1%)로 줄어도 1.6 밑으로 내려가지 않음 → 북마크 하나만 있어도 관심사로 남음. 새 점수가 더 높으면 그대로(`max`). `prepare()` 가 `e.floor` 를 받고 `buildInterests()` 가 북마크이면 `floor` 를 넣음.
- `ACT.note()`: 북마크로 남은 이미지는 점수가 0.05 이하로 떨어져도 활동 기록에서 **지우지 않음**(북마크를 지운 뒤에는 예전처럼 사라짐). `ACT.prune()`: 북마크 이미지는 바닥값 이상으로 취급해 가장 나중에 정리.
- **`seedFromBookmarks()`** (새): 위 둘을 묶어 실행. 호출 시점 — ① 앱 시작(기다리지 않고 뒤에서), ② 동기화로 북마크·활동이 바뀐 뒤(`syncApplied`; "새로 시작"으로 활동이 비워진 직후도 여기서 다시 채워짐), ③ 설정에서 취향 학습을 다시 켤 때, ④ [취향 지우기] 뒤. `info.bm` 이면 활동 캐시(`ACT.m`)도 새로 읽음.
- **[취향 지우기] 동작이 바뀜**: 학습 점수·활동 기록·최근 검색을 지운 뒤 **북마크로 남은 이미지는 바로 다시 채움**(안내 문구에 명시). 북마크 자체를 지우면 함께 사라짐. 뺀 단어는 그대로 존중.
- 부수 효과: 다시 채워진 활동(wt 3 ≥ 2)은 기존 규칙대로 하루 15장 한도 안에서 AI 설명(Workers AI)·의미 벡터 계산 대상이 됨. 북마크가 많으면 며칠에 걸쳐 천천히 채워짐(한도 변경 없음).

### B. 맨 위로 / 아래로 (public/index.html, style.css, app.js)
- 오른쪽 아래(탭바 바로 위)에 둥근 버튼 둘(`#scrollNav`): **▲ 맨 위로**(300px 이상 내려오면 나타남, 부드럽게 이동 — 8화면 넘게 멀면 바로 이동), **▼ 한 화면 아래로**(거의 끝이면 숨김). 피드는 아래로 갈수록 자동으로 더 불러옴. z-index 29 라서 뷰어·설정 같은 전체 화면(50)이 열리면 가려지고, 북마크 선택 모드(`body.selmode`)에서는 숨김. 탭을 바꾸면 다시 판단.
- **탭 다시 누르기**: 지금 보고 있는 탭(피드·트렌드·북마크)을 다시 누르면, 120px 넘게 내려와 있을 때만 **새로고침 없이 맨 위로** 이동. 이미 맨 위면 예전 동작(그 탭을 다시 엶).
- 뷰어(이미지 상세) 안쪽 스크롤에는 넣지 않음(거기엔 기존 [비슷한 이미지]·[닫기] 버튼이 있음). 필요하면 26차에 추가.
- 서비스워커 캐시 v26.

## 검증
- 전체 테스트 20개 파일 통과(`npm install --no-save jsdom fake-indexeddb` 후 `node tests/*.test.mjs`).
- 새로 추가: taste(바닥값 채움·멱등·감쇠 뒤 복구·mute 제외·상한), interests(바닥값으로 오래된 북마크가 관심사로 남음·새 높은 점수는 안 막음), ui(백필·note 유지·학습 꺼짐/비공개·취향 지우기 버튼, 위아래 버튼 표시·동작·탭 다시 누르기), sync.ui(비북마크 활동은 지우면 다른 기기에서도 지워지고, 북마크 이미지는 다시 채워짐).
- 바뀐 기존 기대: `sync.ui.test` 의 "활동을 지우면 B 에서도 0개"는 이제 "북마크가 아닌 활동만 0, 북마크 이미지는 3점으로 다시 채워짐"으로 바뀜.

## 알아 둘 점 / 결정 사항
- 북마크한 이미지가 많으면 오래된 북마크도 바닥값(1.6)으로 계속 관심사에 들어가 최근 취향이 묻힐 수 있음 → 최근 활동은 점수가 더 높아 우선하고, 관심사 3개 뽑기는 중요도 비례라 섞여 나옴. 쓰다가 오래된 북마크가 너무 지배하면 `BM_FLOOR`(interests.js)·`FLOOR_TAG`(taste.js)만 낮추면 됨.
- 한 번에 완전히 "백지"로 시작하려면 이제 북마크도 지워야 함(취향 지우기만으로는 북마크 분이 남음).

- 뷰어 안쪽에도 맨 위로 버튼이 필요한지.
