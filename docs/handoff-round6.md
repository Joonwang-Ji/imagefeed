# 이미지피드 — 6차 작업 결과와 7차 인계 (2026-10-27)

저장소: https://github.com/Joonwang-Ji/imagefeed (main). 변경 파일을 ZIP(imagefeed-round6.zip)으로 전달 → GitHub 웹에서 같은 경로로 덮어쓰기 업로드.
키: Pixabay, Unsplash, 카카오, 네이버 등록됨. 원칙(바꾸지 말 것): 검색·조회 기록 저장 금지, 공포·잔혹 해제 불가, 선정성은 기본 블러+설정에서 해제 가능, 사용자는 본인과 소수 지인(성인).

## 신고 내용 (5차 사용 후기)
- 시카고 미술관만 소스로 고르면 그리드가 정신없이 움직이고 그림은 안 나오며, 소스 탭의 시카고 숫자가 계속 늘어남.
- 전체 소스 검색에서도 시카고 이미지가 나오면 번쩍거리고 이미지는 안 나옴.
- 5차까지의 다른 수정은 대체로 잘 동작.

## 원인 분석 (코드 기준 — 이 환경은 시카고 서버에 접속할 수 없어 실제 응답은 미확인)
두 가지가 겹쳤습니다.
1. **이미지가 안 열림 (뿌리)**: 시카고 어댑터가 작은 그림을 `full/400,/0/default.jpg` 로 요청했음. 시카고가 권장·캐시하는 크기는 843 이고 임의 크기는 거절되거나 매우 느린 것으로 의심됨. 서버 중계(Workers)와 브라우저 직접 로딩(중계 실패 시 대체 경로)이 둘 다 같은 주소를 쓰므로 둘 다 실패 → 그림이 하나도 안 나옴. (IP 차단·Referer 문제라면 둘 중 하나는 열렸을 것이라는 추론에서 "주소/크기 문제"로 판단. 확정은 아님.)
2. **깜빡임·숫자 증가 (증폭)**: 이미지가 끝내 안 열린 카드는 `display:none` 처리만 되고 목록에는 남았음 → 그리드 높이가 0 으로 줄어 화면 아래 "다음 페이지" 감지 지점이 계속 보임 → 같은 소스에서 다음 페이지를 끝없이(최대 50쪽) 불러옴(소스 탭 숫자 증가). 카드가 생겼다 사라지는 것이 깜빡임. 다른 소스는 이미지가 열려서 문제가 드러나지 않았음.

## 6차에서 바뀐 것
- 서버(`src/index.js`): 시카고 이미지를 843 한 가지로 요청(thumb·full), 작은 크기 200 은 예비 주소(alt). 이미지 중계가 artic.edu 로 갈 때 `AIC-User-Agent` 헤더 추가. 중계 실패 시 사유(`upstream 403`, `not an image (text/html)` 등)를 정확히 응답.
- 화면(`public/app.js`):
  - 끝내 안 열린 카드는 목록에서 완전히 제거(`Masonry.drop`).
  - 한 장도 못 연 소스가 4장 연속 실패하면 그 소스를 "쉬게" 함(`DEAD`): 아직 안 열린 카드도 모두 치우고, 그 소스는 더 이상 검색·페이지 불러오기에서 제외 → 깜빡임·무한 불러오기 중단. 한 장이라도 열린 소스는 쉬게 하지 않음.
  - 소스 칩의 ⚠ 를 누르면 이유 표시(예: "이미지가 열리지 않아서 쉬고 있어요 (upstream 403)"), 피드가 비면 안내 문구. 소스 이름을 누르면 쉬는 상태를 풀고 다시 시도. 쉬는 상태는 화면을 연 동안만 기억(저장 안 함).
  - 서버 중계 오류 사유를 `api()` 가 오류에 붙여 둠(`e.detail`).
- 서비스워커 v6, 테스트 추가(서버 9개, 화면 9개). 일부러 수정을 되돌리면 실패함을 확인.

## 검증
- 서버 26개, 화면 84개, 색상 테스트 모두 통과. 시카고 실제 응답·이미지는 확인하지 못함(모의 응답).

## 배포 후 실제 기기에서 확인할 것
1. 시카고 미술관만 선택 → 그림이 나오는지. 안 나오면 약 몇 초 뒤 시카고가 ⚠ 로 바뀌고 쉬는지, ⚠ 를 눌렀을 때 나오는 이유를 알려 주기(예: `upstream 403` = 서버 접속 차단, `upstream 404/400` = 주소/크기 문제, `not an image (text/html)` = 차단 화면).
2. 전체 소스 검색에서 시카고 그림이 정상 표시되는지, 깜빡임이 없는지.
3. 시카고 그림은 AI 선정성 검사(서버 중계 blob 필요)가 되는지 — 중계가 막히고 직접 로딩만 되면 AI 검사는 건너뜀(고전 누드 작품이 있을 수 있어 키워드 필터만 작동).

## 시카고가 여전히 안 될 때의 다음 수
- ⚠ 사유가 `upstream 403`: Workers 서버 주소를 시카고가 막음 → (a) 시카고 소스 제거, 또는 (b) 브라우저 직접 로딩을 기본으로(AI 검사 없이) 전환.
- 사유가 404/400: 이미지 주소 규칙 확인 필요(IIIF `info.json` 로 크기 확인) → 크기 변경.
