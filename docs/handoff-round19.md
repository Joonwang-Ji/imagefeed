키: Pixabay, Unsplash, 카카오, 네이버 등록됨(블로그 소스는 카카오 키를 그대로 씀, 새 키 없음). 원칙(바꾸지 말 것): 검색·조회 기록 서버 저장 금지(기기 안 활동 기록만), 공포·잔혹 해제 불가, 선정성 기본 블러(설정에서 해제), 사용자는 본인과 소수 지인(성인), 기독교 세계관.

## 요청
1. 취향 파악을 한두 단어 키워드가 아니라 문장처럼(다각도로) 인식해서, 키워드 때문에 상관없는 것이 뜨는 문제를 줄이고 추천·비슷한 이미지에 도움이 되게.
2. 티스토리 등 블로그도 검색되게(네이버·다음만 있어 아쉬움).
→ 둘 다 진행(가능성 검토 후 승인).

## 원인 확인 (18차 신고 1번 보충)
홈 ⭐ 칩의 `daum카페`는 카카오 **이미지** 검색 어댑터가 `display_sitename`(출처 사이트 이름)을 `title` 로 넣던 것에서 온 것으로 코드상 확인됨. 제목 단어가 취향·관심사·북마크 단어로 흘러들었음.

## 19차에서 바뀐 것
### A. 블로그 소스 + 출처 이름
- 서버(`src/index.js`): 새 소스 `kakaoblog`(카카오 블로그 검색 `v2/search/blog`, 키는 `KAKAO_KEY`, 끄기 `BLOG=off`). 사진 없는 글은 제외. 제목·본문 일부(`desc`≤160자)·블로그 이름(`site`)을 돌려줌. 하드 차단·선정 판정에 본문 일부도 포함(`textOf`). 카카오 썸네일(`.../argon/130x130_85_c/ID`)은 큰 크기 `600x0_65_wg` 주소를 먼저 쓰고 원래 주소는 `alt` 로 보관(안 열리면 화면이 alt 로 대신).
- 카카오 **이미지**: `title: ""` + `site: <출처 이름>`. 뷰어 제목은 `title → site → 소스 이름` 순.
- 취향 단어에서 출처 이름 제외: `taste.js okKey`, `app.js tokens()/isSiteName` (daum·다음·naver·네이버·tistory·티스토리·kakao·카카오·google·구글·brunch·브런치 + 카페/블로그/뉴스/지식in/포스트…). 예전에 저장된 `daum카페` 제목도 걸러짐.
- 관련도(`relevance.js`): 본문 일부(`desc`)도 판단 재료로 사용. 블로그 소스 가중치: 한글 검색 1.0 / 영어 검색 0.5. TRUST 집합에 넣지 않아(네이버·카카오 이미지와 달리) 안 맞는 글은 구체적인 검색어에서 [관련도 낮은 결과]로 접힘.
- 홈 맞춤 피드(`FY_SRC`)에는 넣지 않음(광고성 글 방지).

### B. 문장 기반 취향
- 서버: `/api/caption` 이 키워드 `q` 와 함께 **설명 문장 `text`(최대 240자)** 를 돌려줌(프롬프트 "한두 문장: 피사체·장소·분위기/스타일·색", `max_tokens` 80, 캐시 키 `cap2`). `/api/embed` 한 글 160→320자, 요청 한도 24→96KB.
- 앱(`app.js`):
  - `embTextOf()`: `설명 문장 | 제목, 본문 일부, 태그` 한 글(출처 이름 제목 제외). 활동 기록·후보 이미지 임베딩 모두 이 함수 사용.
  - `ACT.describePending()`: 활동 점수 2 이상(북마크·좋아요·여러 번 본 것)만 AI 설명을 받아 활동 기록에 `cap`/`cq` 로 저장. **하루 15장**(`DESC_DAY`, LS `capDay`), 한 번에 2장, 비공개·취향 꺼짐·AI 설명 꺼짐이면 안 함, 막힌 설명(공포·잔혹)은 `nc` 로 다시 시도 안 함, 2번 실패해도 `nc`. 설명이 생기면 기존 벡터를 버리고 문장 포함으로 다시 임베딩. 뷰어에서 이미 받은 설명(`it.capText`)은 저장만 하고 다시 호출하지 않음.
  - `Interests.queries()`: 태그·제목이 빈약한 관심사는 설명 핵심 단어(`cq`)를 먼저, 아니면 마지막 예비 검색어로 사용(칩 이름은 그대로 태그 기반).
  - 뷰어 비슷한 이미지 **의미 재정렬**(`simSemantic`): 현재 이미지의 설명 문장(없으면 제목·태그, 부분 검색이면 선택 부분의 설명, 단어 보정이면 고른 단어)과 불러온 상위 40장을 임베딩 → 코사인 유사도. 점수 = 원래 순서 40% + 의미 35% + 색 25%(색 정보가 없으면 순서 50% + 의미 50%). 검색어당 최대 2번, 이미지 근처에 있을 때만, 임베딩 불가면 아무것도 안 함.
  - 설정 안내 문구에 "강한 반응 이미지는 AI가 문장으로 설명해 이 기기에만 저장" 추가. 서비스워커 v18.

## 검증
- 자동 점검 14개 파일 통과(새 `tests/blog.test.mjs` 19개, ui 19차 항목 22개, relevance 4개 추가). 기존 테스트 중 `daum카페` 를 임의 단어로 쓰던 것은 `cafe벚꽃` 으로 바꿈(이제 출처 이름은 학습되지 않으므로), 서버 임베딩 한도(160→320자, 24→96KB) 기대값 갱신.
- 일부러 되돌리면 실패함을 확인: 출처 이름 필터 제거, 카카오 이미지 title 복귀, 의미 재정렬 제거, 모든 활동 설명 대상으로 확대, 관심사 설명 검색어 제거.
- **이 환경은 외부 인터넷·Workers AI·실제 아이폰이 없음 → 아래는 모의로만 확인**: ① 카카오 블로그 응답 필드(`title`·`contents`·`url`·`blogname`·`thumbnail`) ② 카카오 썸네일 큰 크기 주소가 실제로 열리는지 ③ Workers AI 설명 품질·문장 길이 ④ bge-m3 실제 코사인 분포(재정렬 임계 `(cos−0.3)/0.4` 는 17차 값 그대로).

## 배포 후 실제 기기에서 확인할 것
1. 소스 선택에 ‘블로그(다음·티스토리)’가 보이는지, 한글 검색(예: 한옥 마당)에서 블로그 사진이 나오는지, 이미지가 선명한지(흐리면 큰 크기 주소가 안 열려 alt 로 대신하는 것 → 알려 주기: 주소 규칙 조정), 광고성 사진이 많은지(많으면 소스 가중치·접기 기준 조정).
2. 홈 ⭐ 칩에 `daum카페` 같은 출처 이름이 더 이상 안 뜨는지(이미 뺀 단어는 그대로).
3. 북마크를 몇 개 하고 몇 분 뒤 맞춤 피드에서 관심사 품질이 나아졌는지(설명 문장이 쌓여야 함: 하루 15장 한도라 며칠에 걸쳐). Workers AI 무료 사용량 확인(번역·고유명사 판별·설명·임베딩이 함께 씀).
4. 뷰어 비슷한 이미지: 처음 순서 뒤에 1~2초 안에 의미가 가까운 이미지가 위로 올라오는지.

## 알려진 한계·조정 포인트
- 의미 비교는 후보 이미지의 **제목·본문 일부·태그** 글만 봅니다(후보 이미지마다 AI 설명을 만들면 비용이 너무 큼). 제목·태그가 없는 이미지(네이버·카카오 이미지)는 의미 점수가 없어 중간 점수.
- 설명은 영어 문장이라 한글 제목과 섞여 임베딩됨(bge-m3 는 다국어라 비교 가능하지만 한글 단독보다 정확도가 낮을 수 있음).
- 관심사 칩 이름(`label`)은 여전히 태그·제목 단어 기반(설명 단어는 검색어 보조로만).
- 상수: 하루 설명 한도 `DESC_DAY`(15), 설명 대상 점수 `r.wt >= 2`, 의미 재정렬 가중치(0.4/0.35/0.25, `simRerank`·`simSemantic`), 블로그 가중치 `w: 0.9`, 한글 1.0/영어 0.5(`relevance.js bias`).
- 소스 칩의 숫자는 받은 개수, 블로그 썸네일은 ID 만 있는 주소라 `keyOf`(중복 판정)는 호스트+경로 기준.
