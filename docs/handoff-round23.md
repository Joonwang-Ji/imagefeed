저장소: https://github.com/Joonwang-Ji/imagefeed (main). 변경 파일을 ZIP(imagefeed-round23.zip)으로 전달 → GitHub 웹에서 같은 경로로 덮어쓰기 업로드(자동 배포).

키: Pixabay, Unsplash, 카카오, 네이버, 텀블러 등 기존 그대로. 원칙: 공포·잔혹 해제 불가, 선정성 기본 블러, 사용자는 본인과 소수 지인(성인), 기독교 세계관. **"검색·조회 기록 서버 저장 금지"는 17차에 이어 23차에 추가 완화**(아래 결정).

## 요청과 결정 (B1 기기 간 동기화)
"계정정보가 저장되면 좋겠다" → 확인 결과 **기기 간 데이터 동기화**(아이폰·아이패드·맥북).
- 계정: **사람마다 암호 따로**(암호 = 계정). 본인 `PASS`, 지인 `PASS_MORE`(쉼표).
- 범위: **전부**(북마크·보드·메모, 활동 기록(+의미 벡터), 취향, 추천 안 함, 최근 검색, 일부 설정). 서버(D1/R2)에 저장됨 → 원칙 완화.
- 썸네일: **서버에도 저장(R2)**. R2 없이도 레코드만 동기화되게 설계.

## 23차에서 바뀐 것
- 서버 `src/sync.js`: `acctOf`(PASS/PASS_MORE → SHA-256 해시 계정 ID, 상수 시간 비교), `/api/sync`(POST: 올리기+받기 한 번에, 40개씩 올림·100개/350KB씩 받음, 커서 `sv`), `/api/sync/thumb`(PUT/GET, R2), `/api/sync/wipe`. D1 테이블 `sync_items`는 첫 요청에 자동 생성. 레코드 충돌은 `v`(기기에서 고친 시각)가 큰 쪽이 이김(서버 SQL `WHERE excluded.v > v`), 거절된 레코드는 현재 서버 값을 돌려줘 기기가 따라감. 삭제는 tombstone(180일 뒤 정리), 북마크 삭제 시 썸네일도 삭제. `/api/config` 에 `sync`, `syncThumbs`, `acct`(해시 앞 10자).
- 앱 `public/sync.js`(새): 올릴 목록(q, localStorage `sync`에 저장), 처음 켤 때 기기의 모든 것을 올림(설정 값은 v=1 로 올려 서버 값이 이기게), 에코 방지(받은 것은 목록에 안 넣음), 썸네일 업로드(레코드당 1회)·다운로드(3개씩), 계정 확인(`adopt/merge`), `setOn`, `wipeRemote`.
- `public/app.js`: `SYN` 훅 — `LS.set`(KV_KEYS만), `DB.put/del`, `ADB.put/del/clear` 가 올릴 목록에 표시(받은 것을 넣을 때는 `raw=true`). `DB.get`/`ADB.get` 추가. `setupSync/ensureSync/syncApplied/renderSync`: 부팅 2.5초 뒤 동기화, 화면 숨김 시 올리고 돌아오면(60초↑) 받기, 받은 설정은 바로 반영(`S.*`, Taste/Avoid reload), 북마크 수·별·목록 갱신, 활동 캐시 초기화. 설정에 [기기 간 동기화] 칸(체크·상태·[지금 동기화]·[서버 데이터 지우기]), 서버 미연결이면 안내. 개인정보 안내 문구 갱신. 서비스워커 v24(+`/sync.js`).
- 동기화 안 하는 값: 접속 암호, 비공개 모드(`priv`), 하루 AI 설명 한도(`capDay`), 마이그레이션 표시.
- `wrangler.toml`: D1·R2 바인딩은 **주석**으로만(켜기 전에는 앱 동작 변화 없음). 안내 `docs/sync-setup.md`.

## 검증
- 새 점검 3개 파일 + 기존 19개 모두 통과: `sync.server`(48: 계정 격리·충돌·삭제·쪽 나누기·입력 검사·R2·wipe, **진짜 SQL(node:sqlite)** 사용), `sync.client`(41: 두 기기+서버 E2E, 충돌·삭제·오프라인·오류·배치 40개 덮어쓰기 방지·R2 없음·계정/켜기/끄기/wipe), `sync.ui`(진짜 app.js 를 jsdom+fake-indexeddb 로: 설정 UI, 북마크 저장→동기화→두 번째 기기에 나타남·삭제 전파·활동 기록 전파·계정 불일치 확인창).
- 일부러 되돌리면 실패함을 확인: 서버 충돌 보호 제거, 계정 격리 제거, 클라이언트 최신 확인 제거, 에코 방지 제거, 기기 전용 키 동기화, 썸네일 삭제 제거, 북마크 저장/삭제 표시 제거, 받은 설정 즉시 반영 제거, 계정 확인 제거.
- **이 환경은 Cloudflare D1/R2·실제 기기가 없음**: D1 은 sqlite 대역, R2 는 메모리 대역. 아래 "확인 못 한 것" 참고.

## 사용자 해야 할 일 (순서)
1. ZIP 업로드(자동 배포) → 앱은 기존대로 동작, 설정에 "D1 연결 안 됨" 안내가 보임.
2. `docs/sync-setup.md` 따라 D1(필수)·R2(선택) 만들고 `wrangler.toml` 주석 해제 + database_id 입력 → 커밋.
3. 아이폰에서 설정 → 기기 간 동기화 확인, [지금 동기화]. 다른 기기에서 같은 암호로 접속해 북마크 확인.
4. 지인이 쓴다면 `PASS_MORE` Secret 추가.

## 확인 못 한 것 (실서버·실기기)
- 실제 D1 `batch()` 가 DDL·upsert 를 대역처럼 처리하는지, `meta.changes` 값(거절 판정에 사용). R2 `put/get/list/delete(배열)` 시그니처. Workers 무료 플랜 CPU 10ms 안에 들어오는지(JSON 파싱 40개×수 KB, 받기 350KB). 문제 시 `PULL_*`·`MAX_PUSH` 상수 축소.
- wrangler 자동 생성(바인딩에 ID 없이)은 Workers Builds 지원 여부 미확인이라 안내는 ID 직접 입력 방식으로 작성.
- 아이폰 Safari/홈 화면 앱에서 IndexedDB Blob 저장·업로드, 백그라운드에서 전환될 때 올리기(visibilitychange 시 `flush`) 체감.
- 썸네일은 앱이 저장 때 받아 둔 이미지(원본 크기)를 그대로 올림(상한 1.4MB). 용량이 커지면 리사이즈 추가 검토.

## 알려진 한계
- 설정/취향 값은 키 단위 "나중 쪽이 이김"(합치기 아님). 두 기기에서 동시에 학습하면 한쪽이 덮임.
- 동기화 켠 처음에는 활동 기록이 많으면(최대 450개) 여러 번에 나눠 올림(25개씩).
- 암호를 바꾸면 새 계정(빈 데이터). 이전 암호를 `PASS_MORE` 에 두면 이전 계정 접근 가능.
- 서버 소유자는 데이터를 읽을 수 있음(암호화 없음).
- 같은 기기에서 다른 암호로 접속하면 합칠지 확인창(합치기/동기화 끄기). 이 기기 데이터를 지우고 새 계정만 쓰는 버튼은 없음.
