# 이미지피드 — 5차 작업 결과와 6차 인계 (2026-10-26)

저장소: https://github.com/Joonwang-Ji/imagefeed (main). 이 세션에서 코드를 내려받아 수정했고, 변경 파일을 ZIP(imagefeed-round5.zip)으로 전달 → 사용자가 GitHub 웹에서 같은 경로로 덮어쓰기 업로드(`tests/` 폴더는 새 폴더, 올리지 않아도 앱은 동작).
키는 사용자가 등록함: Pixabay, Unsplash, 카카오, 네이버. Brave는 이번에 보류(아래 참고).
원칙(바꾸지 말 것): 검색·조회 기록 저장 금지, 공포·잔혹 해제 불가, 선정성은 기본 블러+설정에서 해제 가능, 사용자는 본인과 소수 지인(성인).

## 4차 테스트 결과 (사용자 답)
- 오프라인: 북마크 열림 → 통과.
- 북마크 검색·정렬·보드·메모, 방향 필터, 뷰어 속도: 문제 없음 또는 아직 안 해봄 → 통과로 둠.
- 색상 필터: 느리고 색이 안 맞는 것이 섞임 → 5차에서 수정.
- AI 설명(📷, [AI로 다시 찾기]): **아직 안 해봄** → 여전히 미확인. "AI 설명을 쓸 수 없어요"가 뜨면 CAPTION_MODEL 로 모델 ID 지정.

## 5차에서 바뀐 것 (사용자가 5차 범위로 선택한 4묶음 전부)
1. **확대·축소 제한**: 화면 전체는 핀치·더블탭 확대 불가(viewport maximum-scale, `touch-action:pan-x pan-y`, iOS gesturestart 차단). 입력칸·select·textarea 글자를 16px로 올림(아이폰이 입력칸에 포커스할 때 저절로 확대하던 것이 "나도 모르게 확대"의 가장 유력한 원인). 뷰어 이미지에서만 핀치·더블탭(2.5배)·확대 후 끌기·Ctrl+휠 확대, 확대 중에는 [원래 크기] 버튼, 1배에서는 좌우 스와이프로 이전·다음(세로는 평소처럼 스크롤).
2. **시트 닫기 UI**: 설정·보드 메모를 아래에서 올라오는 시트로 변경(손잡이를 아래로 끌기, 바깥 탭, Esc, 맨 아래 큰 [닫기]/[취소·저장]). 소스·필터 패널에 [닫기] 추가. 뷰어는 ✕ 를 오른쪽 위로 옮기고 오른쪽 아래에 [✕ 닫기] 떠 있는 버튼 추가.
3. **검색창 ✕**: 입력 중 오른쪽에 ✕, 한 번에 지움(키보드 유지). 북마크 검색창에도 같은 ✕.
4. **색상 필터**: 기본 "정확하게" = 색을 직접 걸러 주는 소스(Pixabay·Unsplash)만 검색(빠르고 정확). 필터 패널의 "넓게 (느림)"을 고르면 다른 소스도 쓰되 브라우저가 대표 색으로 거름(작은 썸네일 `alt`로 색만 분석해서 느린 원본 내려받기 회피). 색 분류 개선(`color.js`: 가운데·선명한 색 가중치, 연한 빨강→분홍, 채도 있는 색 15%/무채색 40% 기준). 안 쓰는 소스는 소스 칩에서 흐리게(…에 멈춰 있던 문제 해결).
5. **홈 추천 주제**: 고정 12개 → 넓은 카테고리 32개(`app.js` 의 `CATS`)에서 열 때마다 무작위 10개 + 북마크 태그 1~2개(⭐), 누르면 세부 주제로 내려감, [🔀 다른 주제]. 🎲는 "아무거나"(세부 주제 무작위)로 이름 변경.
6. **트렌드**: 나라 선택·단어 칩 삭제 → 이미지 그리드. 서버 `/api/trends`(인자 없음)가 위키백과 한국어·영어 많이 본 문서의 대표 사진(grp "news", pageviews top + pageimages API 한 번 호출)과 Pixabay editors_choice·Unsplash 인기 사진(grp "pop")을 번갈아 섞어 줌. 화면은 [전체/요즘 화제/인기 사진], 카드를 누르면 뷰어(비슷한 이미지 포함). svg(깃발·지도) 제외, 공포·선정 제목은 제외, 나머지는 평소처럼 AI 검사 블러.
7. **비슷한 이미지**: (a) 태그가 3개 미만이면 AI 설명 사용(태그 충분하면 AI 없이), 연달아 3번 실패하면 10분 쉼. (b) 검색어에 현재 이미지의 대표 색 이름 덧붙임(한글 검색어면 한글 색 이름, 이미 색 단어가 있으면 생략). (c) 불러온 후보를 현재 이미지와 색 분포가 가까운 순으로 재정렬(원래 순서 50% + 색 유사도 50%, 이미지 근처에 있을 때만, 최대 2번). 색 정보는 이미지 blob 이 있을 때(브라우저 AI 검사 켜짐) 얻음.
8. 서비스워커 v5, README 갱신, `tests/` 추가(색상·서버·화면 자동 점검, `npm install --no-save jsdom` 후 `node tests/xxx.test.mjs`).

## 검증
- 색상 21개, 서버 17개(트렌드 병합·필터·키 유무·실패 시 502, 홈 카테고리가 필터에 안 걸리는지), 화면(jsdom) 70여 개 통과. 중간에 더블탭·스와이프가 안 먹던 버그를 테스트가 잡아 수정함.
- 이 환경은 외부 인터넷이 막혀 실제 응답은 확인하지 못함. 위키 pageviews·pageimages, Pixabay editors_choice, Unsplash /photos?order_by=popular 는 공식 문서 구조 기준으로 모의 응답으로만 테스트됨. 실제 브라우저(아이폰 Safari)도 없어서 핀치·터치 동작은 이벤트 모의로만 확인.

## 배포 후 실제 기기에서 확인할 것
1. 아이폰: 화면 전체가 확대되지 않는지(핀치, 더블탭, 입력창 탭), 홈 화면 앱과 Safari 탭 둘 다. 뷰어에서 핀치 확대·더블탭·확대 후 끌기, 1배에서 좌우 스와이프와 세로 스크롤이 서로 방해하지 않는지.
2. 시트: 설정 시트 손잡이 끌어 닫기, 바깥 탭, 아래 큰 버튼. 뷰어 오른쪽 아래 [✕ 닫기]가 이미지 별(☆)을 가리지 않는지.
3. 트렌드 탭: 이미지가 실제로 나오는지(위키 한·영, 인기 사진), 로딩 속도. 안 나오면 [새로고침]/에러 문구와 함께 알려 주기.
4. 색상 필터: 빨강 등 선택 시 속도·정확도, "넓게"의 속도. 흰 배경 이미지 분류.
5. 비슷한 이미지: 이전보다 색감·소재가 가까워졌는지(색 재정렬은 이미지를 불러온 뒤 약 1초 안에 한 번 순서가 바뀜).
6. 홈: 카테고리가 열 때마다 바뀌는지, 세부 주제 내려가기/뒤로.
7. 아직 못 해본 AI 설명(📷, [AI로 다시 찾기]).

## 결정·보류 메모
- Brave Search API: 2026-02부터 무료 플랜 없음. 월 $5 크레딧(약 1,000회 검색), 카드 등록 필수, 초과 시 과금, 프로젝트에 출처 표기 필요. 결정 보류(사용자가 "의견 없음"). 넣는다면 기본 소스가 아니라 "넓게 찾기" 옵션 + 월 사용량 숫자만 표시를 제안했음.
- 사용자가 "몇 가지 따로 의논하고 진행"하자고 해서 5차 범위는 위 4묶음으로 확정함.

## 남은 후보
- B1 기기 간 북마크 동기화(가장 큼): Cloudflare D1/R2, 같은 암호 보호, 검색 기록은 계속 저장 안 함.
- C2 외부 의존·접속 보호: nsfwjs 모델을 esm.sh 에서 받지 않고 앱 안에 두기, 로그인 시도 제한.
- C3 오래 스크롤할 때 메모리(objectURL 해제 등): 실제 문제가 있을 때만.
- Brave 소스 추가(위 참고).
- 알려진 한계: 색 "넓게"에서 많이 걸러지면 페이지를 계속 불러옴(최대 50페이지), 필터로 카드가 빠진 뒤 칸 높이가 어긋날 수 있음. 색 재정렬은 브라우저 AI 검사를 끄면(blob 없음) 동작하지 않음.
- 색 선택 시 필터 패널이 검색 시작과 함께 닫히는 동작은 그대로(원하면 열어 둔 채 유지하도록 변경 가능).
